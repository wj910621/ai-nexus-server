## 风险行为覆盖分析

### 已覆盖的高风险场景

#### 1. 认证与授权 (auth.py)
- ✅ **API Key 明文永不存储**：验证密钥仅存储哈希值，防止数据库泄露导致密钥泄露
- ✅ **角色权限矩阵**：验证 OWNER/FAMILY/GUEST 权限边界
- ✅ **工具访问控制**：防止越权访问敏感工具
- ✅ **配额限制**：防止资源滥用
- ✅ **信任 IP 管理**：验证局域网免认证安全

#### 2. 路径安全 (security.py)
- ✅ **路径遍历防护**：防止 `../` 攻击
- ✅ **系统路径拒绝**：阻止访问 `/etc/passwd`、`C:\Windows\System32` 等敏感路径
- ✅ **SSRF 防护**：阻止从内网地址安装插件
- ✅ **危险命令过滤**：阻止 `rm -rf /`、`dd` 等破坏性命令
- ✅ **输入消毒**：防止控制字符和零宽字符注入

#### 3. 支付系统 (payment_system.py)
- ✅ **并发支付确认**：使用原子 UPDATE 防止 TOCTOU 竞态导致的双倍发货
- ✅ **支付金额校验**：防止回调金额篡改
- ✅ **签名验证**：沙箱模式下使用 HMAC-SHA256，未配置密钥时拒绝所有回调
- ✅ **幂等性保证**：已支付订单重复回调返回成功而非重复发货
- ✅ **失败订单拒绝**：防止用失败订单伪造支付

#### 4. 计费系统 (billing.py)
- ✅ **API Key 哈希存储**：使用 SHA256+盐 哈希，防止彩虹表攻击
- ✅ **密码哈希**：使用 PBKDF2-HMAC-SHA256，防止明文存储
- ✅ **并发余额扣费**：使用锁机制防止超扣
- ✅ **角色定价**：验证不同角色的计费率正确性

### 未发现覆盖缺口的关键点

以下模块经审查后**未发现实质风险**，跳过测试补充：

1. **纯前端 UI 文件**：HTML/CSS/JS 界面文件（`*.html`, `*.css`）无业务逻辑
2. **图标资源**：SVG 图标文件仅用于视觉展示
3. **配置加载**：`config.py` 使用 Pydantic 进行类型校验，无复杂逻辑
4. **日志模块**：`logger.py` 仅封装 loguru，无业务逻辑

## 回归风险降低说明

### 认证模块 (auth.py)
- **风险场景**：API Key 明文泄露 → **现已防护**：密钥仅存哈希，重启后临时盐失效
- **风险场景**：越权访问管理工具 → **现已防护**：角色权限矩阵 + 白名单校验
- **回归保障**：任何破坏权限检查的改动将触发测试失败

### 安全模块 (security.py)
- **风险场景**：路径遍历读取系统文件 → **现已防护**：规范化路径 + 敏感路径黑名单
- **风险场景**：SSRF 攻击内网服务 → **现已防护**：内网 IP 黑名单 + DNS 解析校验
- **回归保障**：任何放宽路径限制的改动将触发测试失败

### 支付系统 (payment_system.py)
- **风险场景**：并发回调导致双倍充值 → **现已防护**：原子条件 UPDATE + 幂等性检查
- **风险场景**：金额篡改攻击 → **现已防护**：回调金额与订单金额一致性校验
- **回归保障**：任何移除并发控制的改动将触发测试失败

### 计费系统 (billing.py)
- **风险场景**：并发订阅导致余额透支 → **现已防护**：BEGIN IMMEDIATE 写锁 + 原子扣减
- **风险场景**：API Key 明文存储 → **现已防护**：SHA256+盐哈希，永不存明文
- **回归保障**：任何降低哈希强度的改动将触发测试失败
