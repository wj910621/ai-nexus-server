# Production Secret contract

Before a production Helm release, provision a Kubernetes Secret named
`comic-platform` in the `comic-production` namespace. It must be managed by a
cloud secret manager or External Secrets Operator, not committed to Git and not
randomly regenerated by Helm upgrades.

Required keys:

- `APP_SECRET_KEY`: random, at least 32 characters
- `JWT_SECRET_KEY`: random, at least 32 characters
- `DATABASE_URL`: complete production async PostgreSQL URL
- `REDIS_URL`: complete production Redis URL used by the application
- `RATE_LIMIT_REDIS_URL`: production Redis URL used by distributed rate limiting
- `CELERY_BROKER_URL` and `CELERY_RESULT_BACKEND`: production worker queue URLs
- `BILLING_MODE`: `jarvis`
- `JARVIS_GATEWAY_SERVICE_TOKEN`: random billed main-site credential, at least 32 characters
- `YNEX_SSO_SECRET`: same random SSO signing secret provisioned to the main site, at least 32 characters
- `YNEX_BILLING_SERVICE_TOKEN`: same internal billing credential provisioned as
  `STORY_SERVICE_TOKEN` on the main site, at least 32 characters
- `ALERTING_WEBHOOK_URL`: HTTPS operations webhook consumed through the
  Prometheus Operator `AlertmanagerConfig`; alerts must never render an empty
  receiver
- object storage access keys required by the selected provider

The production workflow first deploys the exact same immutable image tag to
staging. Production remains blocked when staging deployment or smoke checks
fail. Helm also rejects production values that use the example hostname,
disable TLS, disable external secrets, or resolve to the `latest` image tag.

Before manually promoting that image to production, create a managed PostgreSQL
snapshot (or an equivalent independently retained, encrypted backup). Supply its
provider evidence ID as `backup_evidence_id` and its UTC completion time as
`backup_evidence_utc`. The workflow rejects missing, malformed, future-dated, or
older-than-60-minutes evidence. Keep the provider restore instructions and
retention policy with the release record; the evidence field is an audit gate,
not a substitute for a tested restore.

Supplier catalogs are not polled automatically by Story Studio. Pricing is
owned by the Y.NEX/Jarvis administration plane. A production promotion must
provide `pricing_evidence_id` and `pricing_approved_utc` for an administrator
published pricing version approved during the preceding 24 hours. The pricing
version must retain provider, model, currency, billing unit, supplier cost,
customer price, effective time, reviewer, and enabled/disabled state. Models
with missing or non-computable cost remain disabled. Routine post-launch review
is performed manually in the Y.NEX administration plane.

Database migrations are expand-only during a release. CI rejects destructive
operations such as dropping tables, columns, constraints, or indexes from an
Alembic `upgrade()`. Contract/removal migrations require a later, separately
approved release after the previous application version can no longer run.

Stripe keys are not required when `BILLING_MODE=jarvis`. Independent checkout
must remain disabled so ComicStudio cannot create a second balance or order
ledger.
